# 负载均衡演进：静态放置 → 空闲偷取 → 在线多臂老虎机策略选择

> 组件：`wateros-task/task-scheduler/scheduler-impl/impl-multi-class`
> 状态：阶段 B 已实现（见 `scheduler/cpu.rs` 与 `api-v0/src/cpu.rs`）；阶段 C 为设计规划
> 关联：`scheduler-impl/impl-multi-class/scheduler.md`、仓库记忆 `wateros-scheduler-load-balance.md`

---

## 1. 背景与问题

SMP 负载均衡的目标是在不破坏调度正确性的前提下，让 $N$ 个逻辑核：

1. **利用率最大化**：尽量少出现“忙核在排队、空核在空转”；
2. **空转最小化**：idle 核能主动吸收其它核的任务；
3. **迁移开销可控**：任务换核会带来 cache/TLB 冷、上下文迁移成本，不能为了均衡而频繁抖震。

本项目此前的问题（记录在 `scheduler.md`）正是“核心数用不满”：

- 放置策略只负责**入队时选核**，任务一旦入队就留在那个核；
- 唤醒路径用 `LastCpu` 回上次运行的核，某个核一旦积压，后续唤醒任务还会继续堆上去；
- **没有 idle pull**：核的队列清空后直接 idle，永远不主动去忙核上“抢”任务。

下面用三个阶段刻画负载均衡能力的演进：**阶段 A（改造前）→ 阶段 B（已实现）→ 阶段 C（在线多臂老虎机，规划）**。

---

## 2. 三个阶段定义

### 阶段 A：仅有静态放置（改造前基线）


| 项        | 内容                                                                |
| ----------- | --------------------------------------------------------------------- |
| 放置      | 新任务`LeastLoaded`，唤醒 `LastCpu`，Yield/Tick 后 `Prefer(当前核)` |
| 迁移      | 无（任务入队后不跨核）                                              |
| idle-pull | 无                                                                  |
| load 度量 | 只数 ready queue 长度（未计入正在运行的 current task）              |

典型失败场景：CPU0 有 3 个可运行任务、CPU1~3 全空转，**永远不会被纠正**——空核既不被放置新任务（没有新任务产生），也不会主动去 CPU0 抢。

### 阶段 B：空闲偷取 + 唤醒亲和放宽（当前已实现）


| 项        | 内容                                                                                                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| idle pull | `pick_next_runnable_or_steal`：所有选 next 决策点（`prepare_first_switch` / `schedule` Phase 4、5-8 / `schedule_wait`）本地无任务时，从最忙其它核偷 1 个；`tick` 中空闲核周期性偷取 |
| 偷取规则  | 源核`load >= 2`（一个在跑 + 至少一个可偷）；FIFO/RR 高优先级优先、fair 偷最小 vruntime；全程校验目标核 `online` 与任务 `affinity`（`CPUState::steal_candidate`）                    |
| 唤醒放宽  | `cpu_is_overloaded`：`LastCpu` 目标核负载超过“平均 + 1”时改走 least-loaded                                                                                                        |
| load 度量 | `CPUState::load()` 已计入非 idle 的 current task                                                                                                                                    |

解决的场景：**忙核排队 + 空核空转**这类静态失衡被主动纠正；唤醒不再一味往重核堆。

仍未解决的局限：

- 偷取**只在“存在空闲核”时生效**；两个都忙的核之间（load 3 vs load 2）不会主动 push 均衡；
- 所有策略参数（偷取阈值、过载阈值、唤醒亲和强度）都是**硬编码常量**；
- 对不同负载形态（通信密集 / 并行突发 / 持续 CPU-bound）用**同一套固定策略**，无法自适应。

### 阶段 C：在线多臂老虎机策略选择（规划）


| 项         | 内容                                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------------------------- |
| 思路       | 不学“怎么排任务”，而是学“**当前阶段该用哪套策略配置**”                                                   |
| 臂         | `LeastLoaded` / `CacheAffine`（纯 last_cpu，去掉过载放宽）/ `AggressiveSteal`（更低偷取阈值 + 更高偷取频率） |
| 决策       | timekeeper 每窗口（如 100~500 个全局 tick）用 UCB 选臂，窗口内按该臂解释`ReadyPlacement` 与偷取参数          |
| 奖励       | 窗口内各核`idle_ticks` 差分方差（均衡度）+ `context_switches`（迁移成本）                                    |
| 非平稳适应 | 每臂收益用 EMA 维护，随负载形态漂移自动切换                                                                  |

关键点：**阶段 C 不改变阶段 B 的数据结构与调度正确性，只把“策略怎么解释/参数取多少”变成可由学习层选择的配置**。接入点很干净——只需改 `pick_ready_cpu` 里 `ReadyPlacement` 的解释和 `steal_ready_task` 的阈值来源。

## 3. 三阶段对比


| 维度                              | A 静态放置   | B 空闲偷取（已实现）    | C 在线老虎机（规划）        |
| ----------------------------------- | -------------- | ------------------------- | ----------------------------- |
| 核心机制                          | 入队选核一次 | 选核 + 跨核偷取         | B 的基础上 + 策略自适应     |
| 纠正静态失衡（忙核排队+空核空转） | ✗ 不纠正    | ✓ 主动偷取             | ✓ 同 B                     |
| 利用空闲核                        | 仅放置时     | ✓ tick/决策点持续偷取  | ✓ 同 B，且可调偷取强度     |
| 对负载形态自适应                  | ✗ 固定      | ✗ 固定                 | ✓ 按 reward 切换           |
| 迁移成本控制                      | —           | 中（偷取即迁移）        | 优（reward 含迁移惩罚）     |
| 每决策开销                        | 极低         | 低（一次 O(核数) 扫描） | 低（窗口级一次 UCB）        |
| 实现复杂度                        | 低           | 中                      | 中高（+遥测/reward/控制器） |
| 可解释、可调试                    | 高           | 高                      | 中（需日志化决策轨迹）      |
| 正确性风险                        | 低           | 低                      | 中（需降级开关兜底）        |
| 答辩创新点                        | 无           | 一般（标准 idle pull）  | 强（“在线学习调度器”）    |

## 4. 优劣判断

### 阶段 A：静态放置

- **优**：实现最简单、零迁移开销、行为完全确定、无任何调试负担。
- **劣**：
  - 负载失衡**只进不出**，随时间累积；
  - 空核永远空转，核心利用率上不去；
  - “忙核排队、空核空转”直接对应 benchmark 分数损失。
- **结论**：只适合作为最早期 bring-up 的底座，**不具备参赛竞争力**。

### 阶段 B：空闲偷取 + 唤醒放宽（当前）

- **优**：
  - 直接命中“核心数用不满”这一核心痛点，收益立竿见影；
  - 正确性风险低：不改变状态机，只在“选 next 时本地为空”这一精确时机补一次偷取；源核 `load>=2` 与 affinity 校验防止了偷错/抖震；
  - 实现集中（`scheduler/cpu.rs` + `CPUState::steal_candidate`），每决策开销只是 O(核数) 扫描。
- **劣**：
  - 策略参数是常数，**不同负载形态共用同一套**：通信密集的负载可能因过早偷取损失缓存亲和，纯 CPU-bound 负载又可能因偷取阈值太高而错过平衡机会；
  - 只解决“有空核”的情形，两个都忙的核之间不主动 push 均衡；
  - 属于“标准做法”，答辩创新点有限。
- **结论**：**必做的正确性/性能底座**，但不是终点。

### 阶段 C：在线多臂老虎机

- **优**：
  - 让“用哪套策略”成为**自适应决策**，能跟随负载形态漂移（libc-test → LTP → UnixBench 阶段自动切换）；
  - reward 显式包含迁移成本，**天然抑制过度偷取/抖震**，比固定阈值更稳；
  - 全定点、窗口级决策，热路径零开销；
  - 答辩叙事强：“基于在线学习的负载均衡层”。
- **劣**：
  - 收益有天花板：B 已拿到大部分均衡收益，C 主要是“最后一点 + 自适应卖点”；
  - 引入遥测聚合、reward 设计、UCB 参数（$\alpha$、$c$、窗口长），调试面变大；
  - reward 设计不当会学到“次优策略”，需要日志/降级开关兜底；
  - 若讲不清 reward 合理性、收敛性，答辩反而减分。

## 5. 结论与建议

1. **正确性 > 性能 > 创新**：任何 ML 层都必须以“测例全过时默认回退纯启发式”为前提。
2. **路径**：阶段 B 已是必做且已完成的底座；阶段 C 应作为**加分层**在其上实现，不重写机制。
3. **推荐落地顺序**：
   1. 先加遥测探针（每核 `idle_ticks`/`context_switches`/`timer_ticks` 窗口差分）与 procfs/日志导出；
   2. 实现 `LoadBalancerController`（EMA + UCB，全整数），先在 `LeastLoaded`/`CacheAffine` 两臂间做窗口级切换；
   3. 加 feature 开关与“软切换”（概率混合 + 迟滞），跑正式测例对比 B；
   4. 若收益为正且稳定，再扩展 `AggressiveSteal` 臂与参数自适应。
4. **答辩叙事**：“在保证启发式正确性不变的前提下，用在线多臂老虎机在最小负载、缓存亲和、激进偷取之间自适应选择，reward 直接度量核间空闲方差与迁移成本，显著降低混合负载下的空转率。”

## 6. 附录：奖励信号与 UCB（定点化）

### 6.1 奖励

每窗口结束后，timekeeper 收集全核遥测差分：

$$
\text{imbalance} = \frac{\mathrm{std}(\Delta idle\_ticks_i)}{\mathrm{mean}(\Delta idle\_ticks_i)+1}, \qquad
\text{migration} = \frac{\sum_i \Delta context\_switches_i}{\sum_i \Delta ticks_i}

$$

$$
r = w_1\,(1 - \text{imbalance}) - w_2\,\text{migration}

$$

归一化到 $[0,100]$ 整数；`idle_ticks` 与 `context_switches` 在 `CPUState` 已有，无需新计数。

### 6.2 UCB1 选择

每个臂维护选择次数 $n_i$ 与 EMA 收益 $\hat\mu_i$，每窗口选：

$$
i^* = \arg\max_i \left( \hat\mu_i + c\sqrt{\frac{\ln N}{n_i}} \right), \qquad N=\sum_i n_i

$$

- 前 $K$ 个窗口强制每个臂至少各试一次（warm-up），避免 $\ln N$ 除零；
- $\sqrt{\ln N / n_i}$ 用**查表**（$N$ 到几十足够）或整数近似，避免浮点；
- EMA：$\hat\mu_i^{(t)} = (1-\alpha)\hat\mu_i^{(t-1)} + \alpha\, r_i^{(t)}$，典型 $\alpha\in[0.1,0.3]$。

### 6.3 防抖震

- **软切换**：按概率混合主臂与次优臂（如 80/20），而非整窗硬切；
- **迟滞**：两臂收益差小于阈值时保持当前臂；
- **降级开关**：feature 关闭时阶段 C 完全不参与，行为与阶段 B 完全一致。
