# K-05B 阶段结果：O(1) page-cache LRU

## 本次范围

旧 page cache 在每次 hit、evict、purge 和 truncate 时通过
`VecDeque::iter().position()` 查找槽位，容量 4096 时为 O(capacity)。rustc 的共享库
按 4 KiB 缺页读取，会高频进入该临界区。

## 修改结果

- 每个预分配 slot 保存 `prev/next/class`，不移动 4 KiB page data。
- clean 和 dirty 分别维护侵入式双向 LRU。
- touch、insert、remove、class 迁移和 pop 均为 O(1)。
- 保留 clean-first 驱逐：只要存在 clean page，cache miss 就不会被无关 dirty
  temporary file 的 writeback 阻塞。
- flush 按 version 确认后把 slot 从 dirty LRU 移到 clean LRU。
- 测试构建增加完整不变量检查：链表无环/无重复，index、free、key、dirty class
  一致。
- 未修改 `wateros-task` 代码、API、调度器或生命周期。

## 验证结果

- page-cache host test：9/9 通过，覆盖重复 touch、clean/dirty 迁移、clean-first
  eviction、flush race、truncate、purge 和 close。
- `make rv_check`：通过。
- `make la_check`：通过。
- `make kernel-rv-final`、`make kernel-rv-pre`：通过。
- fresh final qcow2：CAgent 10/10，10.88 秒；BuildStorm toolchain/minibuild 通过。
- fresh `tg-xtask` 到 21/446：改动前约 10分21秒，本次约 8分27秒，单轮缩短约 18%。
- 12 分钟诊断窗口到 22/446，无 SIGSEGV、panic、BadFd 或 page-cache 错误。

## 未闭环项

- 单轮计时只能证明命中热路径，不能替代三轮稳定基准。
- final 在活跃编译时由诊断 timeout 终止，未得到完整 BuildStorm 标记，也不能用该
  overlay 做崩溃一致性 `e2fsck` 验收。
- 初赛 LTP 运行到 epoll 后内核堆从约 120 MiB 增长到 128 MiB 并 OOM panic；
  同时存在已有的 `/proc/meminfo` 缺失。该问题转入 K-07C 堆与资源回收任务。
