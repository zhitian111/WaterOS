# K-01 阶段结果：目录 fsync 持久化契约

## 本次范围

本次完成 K-01 中 `fsync/fdatasync` 的句柄能力分发。旧实现由 syscall 层先读取
metadata，并拒绝所有非普通文件，导致 Cargo 在 `tg-xtask` 阶段对目录 fd 执行
`fsync` 时得到 `EINVAL`：

```text
[WARN] [syscall] fsync fd=6 flush failed: Unsupported
```

## 修改结果

- `ReadWriteFs` 增加 `sync()` 契约，由文件系统实现提交内部缓存和块缓存。
- another-ext4 的 `sync()` 调用真实 `flush_all()`；ramfs 因数据已提交到内存树而成功。
- 根卷和可写辅助挂载的目录句柄将 `flush()` 路由到所属文件系统。
- `fsync/fdatasync` 不再维护节点类型白名单，只委派给打开句柄。
- `VfsIoHandle::flush()` 默认返回 `Unsupported`，防止 pipe、socket 和设备伪造持久化
  成功；普通文件和目录由各自句柄覆盖。
- 未修改 `wateros-task` 的 API、实现、调度器或资源生命周期。
