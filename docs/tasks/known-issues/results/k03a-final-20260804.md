# K-03A regex_search 四配置最终复验

## 结果

使用初赛镜像自带的完整原始 `libc-bench`，RISC-V64/LoongArch64 与 glibc/musl 四种
组合均运行到末尾 regex 段并退出 0。两个历史 0 分 search 项均输出有效非零耗时：

| 架构 | libc | `(a|b|c)*d*b` | `a{25}b` |
|---|---|---:|---:|
| RISC-V64 | glibc | 0.021261800 s | 0.132493600 s |
| RISC-V64 | musl | 0.061099100 s | 0.113679700 s |
| LoongArch64 | glibc | 0.004804230 s | 0.093564380 s |
| LoongArch64 | musl | 0.048204840 s | 0.153798770 s |

四次 compile 项也正常，最终均输出 `K03A_RESULT failed=0`。没有依靠增加用户栈、修改
benchmark、跳过前置测试或放宽结果解析。

## 验证方法

每个架构以 8 CPU、1 GiB 启动现有 LTP bringup 内核，在镜像内分别执行：

```sh
cd /glibc && ./busybox timeout 900 ./libc-bench
cd /musl  && ./busybox timeout 900 ./libc-bench
```

RISC-V 全轮约 139 秒，经历约 15010 次线程 clone/exit；LoongArch 全轮约 19 秒。两轮
均无用户 fault kill、signal frame 失败、panic、fatal trap 或永久任务阻塞。
