# K-03C BusyBox kill、mv、rmdir 双架构复验

## 结果

K-03C 的历史 0 分项在当前内核上已经闭环。使用同一最小脚本分别调用初赛镜像中的
glibc 和 musl BusyBox，并在 RISC-V64/OpenSBI 与 LoongArch64/QEMU 上以 8 CPU 运行，
四种组合全部输出：

```text
K03C libc=glibc fs=true
K03C libc=glibc signal=true
K03C libc=musl fs=true
K03C libc=musl signal=true
K03C_RESULT failed=0
```

## 覆盖语义

每个 libc 组合均从独立干净路径执行：

1. 创建源目录并 `mv` 到新路径；
2. 验证目标为目录，随后 `rmdir` 并验证路径消失；
3. 创建后台 `sleep`，以 `kill -0` 确认存在；
4. 发送默认 SIGTERM 并 wait 回收；
5. 验证已回收 PID 和不存在 PID 的 `kill -0` 均失败。

这避免了旧评分脚本中 `mv` 失败导致 `rmdir` 连锁失败的问题，也确认 glibc 与 musl
BusyBox 没有走不同的内核特判。
