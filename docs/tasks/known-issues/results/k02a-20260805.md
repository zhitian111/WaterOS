# K-02A 跨核迁移发布竞态修复报告（2026-08-05）

## 现象与根因

RISC-V 8 核反复执行 `sched_setaffinity` 与跨核 TLB 测试时，曾随机出现 CPU 2
`InstructionPageFault`，`pc=0`。GDB 现场显示源 CPU 与目标 CPU 同时使用同一任务的
内核栈，栈指针仅相差约 1 KiB。

根因位于 multi-class scheduler：当前任务被 affinity 强制迁出时，scheduler 在源 CPU
调用 `__switch` 保存上下文之前，已经把该任务加入远端 runqueue 并发送 reschedule
IPI。目标 CPU 因而可以提前运行同一任务、上下文和内核栈。

## 修改

- `impl-multi-class/src/scheduler.rs` 增加每 CPU 的延迟迁移槽。当前任务仅在 affinity
  仍包含本 CPU 时立即重新入队，否则暂存到该槽。
- `impl-multi-class/src/lib.rs` 在 `__switch` 返回后发布延迟任务，再于 scheduler 锁外
  发送目标 CPU reschedule。
- `wateros-task/src/runtime.rs` 在用户、内核和 idle 的首次运行入口完成发布，覆盖新建
  context 不会从旧 `__switch` 返回的路径。

该修复不改变 `api-v0`、TCB 布局或平台接口，硬件 IPI 细节仍由 platform 层负责。

## 定向验证

两台 QEMU 同时运行，使用独立 snapshot 镜像和宿主 CPU 集：RISC-V 固定到
`0,2,4,6,8,10,12,14`，LoongArch 固定到 `16-23`。

- 双架构均报告 `online=8`；CPU 1--7 各自设置并回读单 CPU affinity，各完成 10,000
  次 semaphore 睡眠/远端唤醒，每架构共 70,000 次。
- RISC-V 完成 10,000 轮 CPU0/CPU1 `mprotect(RW -> R -> RW)`，远端写入按预期触发
  SIGSEGV，恢复写权限后可继续写入。
- LoongArch 完成同量 CPU0/CPU1 迁移和条件变量唤醒；该架构当前 `sigaction` 返回
  `EINVAL`，因此本轮未声称完成 LoongArch TLB shootdown 验收。
- `make rv_check`、`make la_check` 以及双架构 pre/final kernel 构建通过。
- 主工作区双架构 final 冒烟均完成 CAgent，进入 BuildStorm 并输出
  `BUILDSTORM_TOOLCHAIN ok`；随后按短测策略主动停止，未作为完整 BuildStorm 结果。

关键日志已备份到 `os/debug-reports/archive/k02a-20260805/`。PASS 日志 SHA-256：
RISC-V `292b485d...2a2d77`，LoongArch `12e58bc2...260e7`。

## 剩余工作

K-02A 尚不能整体归档：需要补齐 LoongArch TLB 等价压测、每 CPU timer/idle 证据和
IPI pending/clear 无 storm 记录。两架构的 `sched_getcpu()` 当前返回 `-1`，也应作为
独立 syscall/VDSO 兼容性问题处理；它不影响本次 affinity 设置与迁移竞态结论。
