# K-01 BuildStorm 与文件系统持久化完成报告

## 结论

K-01 在提交 `05d444cc` 上完成。RISC-V64/OpenSBI 与 LoongArch64/QEMU 均以 8 CPU
通过 final CAgent 和完整 BuildStorm；初赛 glibc/musl basic、busybox 也通过。所有
正式写盘验证均使用独立 qcow2 overlay，合并后通过 `e2fsck -fn` 五阶段检查。

## 修复闭环

| 范围 | 关键提交 | 结果 |
|---|---|---|
| 目录与文件 `fsync` | `dad1fcb3` | 由句柄能力分派，another-ext4 执行真实 `flush_all()` |
| 大读写短进度 | `c17692d8` 及 read-family 系列 | 不再把 4 MiB staging 上限暴露为 `EINVAL` |
| 页缓存失败与身份 | `f9f925e7`、`12747bcb`、`659641e4`、`85c6f5af` | 失败可重试，unlink/rename 后不写错 inode |
| ext4 元数据兼容 | `285cdb64`、`5661b8dc`、`b447d9b5`、`9e2cd7cf` | 索引目录、lazy bitmap 和目录尾校验闭环 |
| close/扩展写顺序 | `496334e3`、`598a6cb1` | close 不做全局 sync；掉电不留下 extent 越过 EOF |

`fsync fd=6` 的历史警告来自 Cargo 对目录 fd 调用 `fsync`，不是 pipe/socket。修复后
双架构完整日志均无 `flush failed`。重启后的增量 BuildStorm 没有重新编译 crate，
证明 1970 时间戳和 Cargo last-use warning 当前不破坏 target 复用，因此没有无依据
扩展 FS/VFS 时间戳公共契约。task API、scheduler 分层和 task 生命周期架构均未修改。

## 环境故障判读

一次 RISC-V 临时 overlay 运行曾在 another-ext4 写块时得到 `IoError`。QEMU trace
给出 `blk_co_pwritev ... ret -122` 和 virtio status 1；`-122` 是宿主 `EDQUOT`。
`/tmp` 挂载参数包含 `usrquota`，清理旧测试镜像后可用空间由 3.1 GiB 恢复为 15 GiB，
随后相同内核和基线通过。该轮 overlay 的 ext4 确有未连接 inode/位图差异，但根因是
宿主拒绝写入，不计为 WaterOS 回归，也不能用来证明 guest 块设备竞态。
