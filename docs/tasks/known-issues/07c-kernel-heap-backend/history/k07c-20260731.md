# K-07C 阶段结果：fork/wait 回收竞态与内核栈泄漏

## 结论

初赛 LTP 在 `epoll_ctl` 阶段耗尽 128 MiB 内核堆的直接原因不是 allocator
碎片，而是 process registry 与 scheduler 分两阶段发布退出状态时存在回收竞态。
父进程可能先观察到 process 已退出，随后在 scheduler task 尚未进入 `Exited` 时回收。
旧 `TaskRegistry::reap_task()` 会先移除 TCB，再发现它还不能生成 `ExitedTask`，造成
32 KiB 内核栈永久丢失，并使后续 `waitpid` 返回 `ECHILD`。

临时 size-bucket 探针在 90% 堆占用时记录到：

```text
live allocations: 749, 4911, 4125, 4133, 2979, 9
live bytes:        21032, 801736, 2661120, 16852576, 97483552, 2990832
buckets:           <=64, <=256, <=1024, <=4096, <=32768, >32768
```

其中约 97.5 MiB 是 2,979 个接近 32 KiB 的分配，与
`KERNEL_TASK_STACK_SIZE = 32 * 1024` 一致。诊断探针已全部删除。

## 修改

- scheduler registry 仅允许移除已经处于 `TaskState::Exited` 的 TCB。
- task 聚合层在所有 scheduler task 均终止后才移除 process 和释放地址空间。
- `waitpid/waitid` 遇到 process 已发布退出、scheduler 尚在完成切换的短窗口时 yield
  后重试；被 `SIGCHLD` 唤醒后优先重新检查可见的子进程事件。
- 销毁用户地址空间时释放已失效 VMA vector 和 demand-page loader 的容量，仅保留供
  旧 raw handle 检查的 tombstone。
- `execve` 加载或准备失败时释放新地址空间，并把可失败的信号状态准备移到兄弟线程
  清理之前。

task 的 process/scheduler 分层没有合并：process registry 仍拥有进程与地址空间，
scheduler 仍拥有 TCB；聚合层只协调两个既有生命周期。
