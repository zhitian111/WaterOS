# 最新候选双架构 Final 验证报告

## 结论

提交 `1898f408` 的内核代码在 RISC-V64/OpenSBI 和 LoongArch64/QEMU 上均以 8 个
虚拟 CPU 完成 CAgent 与完整 BuildStorm。两架构 CAgent 均为 10/10，BuildStorm
均通过 toolchain、minibuild 和并行编译门禁，测试命令退出码为 0，未观察到内核
panic、SIGSEGV、OOM 或文件系统 I/O 错误。

本轮用于验证最新代码未破坏 K-01 已关闭的 BuildStorm 路径，不替代 K-10 要求的
三轮 CAgent、pre/LTP/read-family、性能消融或写后 overlay `e2fsck`。

内核从独立 worktree 构建。测试配置仅将 final 队列临时调整为 CAgent 后 BuildStorm，
与主工作树中已有的未提交配置一致；该顺序调整未进入本报告提交。两个 QEMU 均使用
`-snapshot`，因此基础 raw 镜像在运行后 hash 不变。受宿主可用内存约 11 GiB 限制，
两个 8 GiB 客户机顺序运行，未用交换空间换取表面并发。

## 运行结果

| 架构 | CAgent | BuildStorm | 编译耗时 | 产物 | 总命令结果 |
|---|---:|---|---:|---:|---|
| RISC-V64 | 10/10 | `mode=multi ok=true` | 1478.69s | 1,681,000 B | exit 0 |
| LoongArch64 | 10/10 | `mode=multi ok=true` | 1594.53s | 1,714,568 B | exit 0 |

LoongArch 日志中的 Cargo `failed to save last-use data` / `out of range integral type
conversion attempted` 来自镜像内工具链对 1970 时钟的缓存记账；minibuild 和完整编译
随后成功，不是本轮失败。
