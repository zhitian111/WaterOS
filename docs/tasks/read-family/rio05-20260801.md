# RIO-05 完成报告：pipe 与 Unix socket 读取提交

## 结果

RIO-05 已完成。pipe byte stream、`O_DIRECT` packet pipe、Unix stream 和 Unix
datagram 均接入 RIO-04 的 `VfsReadLease`，用户复制发生故障前不再破坏性消费底层数据。
实现未修改 task 模块，只使用其既有 `WaitQueue` 和中断返回协议。

## 修改内容

- `wateros-ipc/ipc-pipe`：增加公开的 pipe read lease 契约；ring buffer 记录 stream/
  packet segment 和唯一 active reservation。stream 部分 fault 只提交已复制前缀，首字节
  fault 与 lease Drop 回滚；packet 成功读取或部分 fault 均消费当前 packet，截断不跨越
  packet 边界。
- pipe reservation 继续计入容量；其它 reader 通过既有 waitqueue 等待，不使用轮询。
  commit/cancel、写端关闭和最后一个读端关闭均执行对应唤醒；最后一个读端关闭会撤销
  active reservation。
- `wateros-vfs/impl-fd-session`：`PipeReadHandle` 和 `UnixStreamPairEnd` 将 pipe lease
  适配到统一 VFS lease。
- `wateros-syscall/impl-kernel`：Unix datagram 使用共享 inbox reservation，`read` 与
  `recvfrom` 共用消费协议；阻塞等待由 sleep polling 改为 waitqueue。`dup`、`dup3`、
  `F_DUPFD` 和 `F_DUPFD_CLOEXEC` 同步 Unix socket 注册，关闭被复制前的 fd 后新 fd 仍可用。

主要涉及目录：

```text
os/components/wateros-ipc/ipc-pipe/
os/components/wateros-vfs/vfs-impl/impl-fd-session/
os/components/wateros-syscall/syscall-impl/impl-kernel/src/
```

## 语义确认

宿主 Linux 差分结果显示，Unix datagram 跨页部分 fault 返回 `EFAULT` 并消费整包；本实现
据此在 `copied > 0` 时消费整包。任务文档明确要求首字节 fault 保留整包，因此
`copied == 0` 时回滚到队首。packet pipe 同样保持记录边界，不套用 stream 的前缀提交
规则。

## 验证

- 组件启动自测覆盖：stream 部分/零字节 fault、Drop 回滚、reservation 容量、第二
  reader、packet 截断与部分 fault、写端关闭后数据再 EOF、读端关闭撤销 reservation。
- RISC-V64、8 核 QEMU 定向测试输出 `RIO05_PIPE_UNIX_PASS`：覆盖 pipe、Unix stream、
  packet pipe、Unix datagram 的无效指针和跨页故障路径。
- RISC-V64、8 核 QEMU dup 回归输出 `RIO05_UNIX_DUP_PASS`：覆盖 `dup`、`dup3` 和
  `F_DUPFD_CLOEXEC` 后关闭旧 fd 的 Unix datagram 收发。
- `make rv_check`：通过。
- `make la_check`：通过。
