# RIO-02 用户写入进度实现报告

## 结果

RIO-02 已完成。MM API 现在能同时返回已经写入用户空间的精确前缀长度和后续错误，
原有 `copy_to_user()` 仍保持全量成功或返回 `MmError` 的兼容语义。syscall 层已提供
对应的 errno 进度包装，但本任务没有提前迁移 read 调用族。

## 实现

- `UserCopyProgress { copied, error }` 位于 `wateros-mm-api-v0`，不依赖 syscall errno。
- Sv39 和 LoongArch64 每页均先完成 fault/COW、权限检查和 PA 翻译，再复制该页。
- 两套实现不再用循环内的 `?` 丢弃 `done`；地址范围溢出在首次写入前返回
  `InvalidAddress`。
- 空输入不读取用户地址，返回 `{ copied: 0, error: None }`。
- `UserWriteProgress` 使用既有 `mm_err_to_errno()`，未把 OOM 强制压成 `EFAULT`。
- 聚合层提供 `mm::test_user_copy_progress()`，依次执行 API、Sv39 和 LoongArch64
  软件页表自测。

## 定向测试

组件自测覆盖：

1. 单页完整复制；
2. 两个有效页的跨页复制；
3. 第一页尾部成功、第二页未映射时的精确部分进度；
4. 不可 COW 只读页在写入前失败；
5. 地址末尾溢出和零长度地址不访问；
6. COW 后父页不变、子页获得独立副本；
7. 旧 `copy_to_user()` 保留原错误。

验证结果：

- `make rv_check`：通过。
- `make la_check`：通过。
- 临时在 MM 初始化后调用聚合自测，执行 `timeout 10s make rv_pre_run`：两套页表
  自测均通过，内核随后进入驱动、FS 和 VFS bring-up；到期由 timeout 主动终止。
- `make la_pre_run` 因仓库缺少 `os/sdcard-la.img` 无法启动；不挂盘和临时空盘的
  LoongArch QEMU 均停在既有早期 logo 阶段。因此 LoongArch 原生启动未作为通过项，
  其实现由 RISC-V 内核内执行同一 LoongArch 软件页表自测补足。
