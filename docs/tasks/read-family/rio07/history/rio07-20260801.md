# RIO-07 完成报告：eventfd 原子读取提交

## 结果

RIO-07 已完成。eventfd 的 8 字节读取现在通过现有 `VfsPreparedRead`/
`VfsReadLease` 契约执行：建立 reservation 时只捕获 counter，完整用户复制成功后才扣减；
任意部分复制、首字节 fault 或 lease Drop 都取消 reservation，counter 保持不变。实现未修改
`wateros-task` 的 API、调度器或等待队列架构。

## 修改内容

- `sys/ipc/eventfd.rs` 在共享 `EventFdState` 中维护唯一 active read reservation 和递增
  generation。同一 eventfd 的其它 reader 在 reservation 结束前等待；nonblocking reader
  返回 `EAGAIN`。
- normal 模式提交 reservation 捕获的值，semaphore 模式只减 1。reservation 期间的并发
  write 直接累加 counter，提交时只减旧值，不覆盖新增值。
- eventfd `read()` 与 syscall 的 prepared-read 路径共用同一 lease；poll 在 active
  reservation 期间不错误报告可由第二个 reader 消费的 `POLLIN`。
- `/boot/config-5.15.0` 现在声明 `CONFIG_EVENTFD=y`，避免 LTP 将已实现能力判为 TCONF。
- 从 LTP fast-exit 表移除 `eventfd01..05` 和 `eventfd2_01..03`。依赖镜像未提供的
  libaio 的 `eventfd06` 仍保留。

## 验证

- `make rv_check`：通过。
- `make la_check`：通过。
- `make kernel-rv-ltp-glibc`：通过。
- RISC-V 初赛 glibc LTP 定向 QEMU：`eventfd01..05`、`eventfd2_01..03` 全部退出 0，
  共 23 条 `TPASS`，无 `TFAIL`、`TBROK`、panic、fatal trap 或超时。
- 定向运行使用 `rv_qemu_run_snapshot`、120 秒上限和独立 qcow2 overlay；原镜像 runner
  测试后逐字节恢复。日志：`/tmp/wateros-rio07-qemu-final-18108.log`。

LTP 20240524 的上述 eventfd 用例覆盖短 buffer、nonblocking、poll/select、fork 共享、
descriptor/status flags 和 semaphore 并发，但不构造无效或跨页用户 buffer。EFAULT 后
counter 保留由 lease 的 `complete && copied == 8` 提交条件保证；RIO-10 仍需在 8 核下做
首字节/跨页 fault、并发 write 和 owner exit 的统一差分压力门禁。完整初赛 LTP、final
CAgent 与 BuildStorm 按白天测试约束未在本任务运行。
