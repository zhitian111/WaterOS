# RIO-08 完成报告：字符与伪设备事务读取

## 结果

RIO-08 已完成。UART、headless console 和 `/dev/urandom` 等消费型读取现在通过
`VfsPreparedRead`/`VfsReadLease` 在用户复制成功后提交；首字节 fault、部分复制和 lease
Drop 会保留未提交数据或只推进已复制前缀。实现未改动 task、调度器或等待队列架构。

## 修改内容

- character `api-v0` 新增 `CharacterReadReservation`、`CharacterReadFinish` 以及可选的
  `prepare_read`/`finish_read` 契约。真实消费型 driver 不支持该契约时明确返回
  `Unsupported`，VFS 不再退回破坏性 `read()`。
- `SerialPortCharacterDevice` 增加软件 pending FIFO 和唯一 active reservation。poll
  探测到的 UART 字节先进入 FIFO，不再被 poll 丢弃；partial/fault 时未提交后缀按原顺序
  放回队首，user-copy 期间不持 driver 锁。
- `CharDevHandle` 将 driver reservation 适配为 VFS lease；headless 合成输入使用同样的
  reserve/commit/rollback 状态机。`/dev/null` 和 RTC stub 返回 EOF lease，且 null 不再
  被误报为 TTY。
- `/dev/zero` 使用无状态生成 lease；ConsoleIn、`/dev/null`、RTC 和
  `/dev/cpu_dma_latency` 使用轻量 EOF lease。
- `/dev/urandom` 的 PRNG state 改为串行 reservation。首字节 fault 不推进 state，partial
  fault 只推进已复制字节；reservation 期间的并发写入 entropy 在提交或取消时合并。
- syscall prepared-read 路径会重试 `acquire()` 返回的 `Busy`，允许共享消费源在 active
  lease 结束后继续读取。

## 设备矩阵

| 对象 | lease 类型 | fault/partial 行为 |
|---|---|---|
| UART/serial TTY | FIFO reservation | 回滚未复制后缀，保持顺序 |
| headless console | 全局输入 reservation | 只推进 copied 前缀，Drop 回滚 |
| `/dev/urandom` | 串行 PRNG reservation | 只提交 copied 对应 generation |
| `/dev/zero` | stateless generated | 返回 copied 个零字节 |
| null/ConsoleIn/RTC/cpu_dma_latency | EOF snapshot | 返回 0，不消费状态 |

## 验证

- `make rv_check`：通过。
- `make la_check`：通过。
- `make kernel-rv-ltp-glibc`：通过；测试内核临时执行 UART fake FIFO、headless、zero 和
  urandom 状态机自检，无断言、panic 或 fatal trap。临时入口未保留在源码中。
- RISC-V 初赛镜像短时 QEMU：LTP `read02` 为 3 TPASS、0 failed/broken，验证
  `EBADF`、`EISDIR` 和 `EFAULT`；lmbench `lat_syscall -N 1 read/write` 对
  `/dev/zero` 与 `/dev/null` 均退出 0。
- 定向运行使用 `rv_qemu_run_snapshot` 和 120 秒上限；实际用时约 5 秒。镜像中的
  `/glibc/ltp_testcode.sh` 已恢复并通过 `cmp`。日志：
  `/tmp/wateros-rio08-qemu.log`。

当前自动化没有向 QEMU UART 注入真实外部字节，因此真实 UART 的 fault/partial 行为以同一
`SerialPortCharacterDevice` 上的 fake FIFO 自检为证据；RIO-10 仍需在 8 核环境加入真实
UART 注入、并发 reader 和 owner-exit 压力。按白天约束，本任务未运行完整 LTP、CAgent
或 BuildStorm。
