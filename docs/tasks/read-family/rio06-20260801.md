# RIO-06 完成报告：inet socket 非破坏性接收

## 结果

RIO-06 的实现阶段已完成。TCP、UDP 和内核 UDP loopback 现在通过同一个 receive lease
执行 peek、用户复制和受控提交；`read`、`recv`/`recvfrom`、`recvmsg` 不再在用户复制前
消费 socket 接收队列。同一 socket 同时只允许一个 active reservation，用户复制期间不
持有 `NETWORK_STACK` 锁。

## 修改内容

- socket metadata 增加 reservation generation。poll/readiness 在 reservation 生效期间
  隐藏队首可读状态，避免 dup/fork reader 越过保留前缀。
- TCP 使用 smoltcp `peek_slice` 暂存数据，成功后只消费 copied 前缀；首字节 fault、
  `MSG_PEEK` 和 lease Drop 均取消 reservation 而不消费。
- UDP 使用 smoltcp `peek`，loopback 使用 `VecDeque::front`。成功短读提交整包，
  `MSG_TRUNC` 返回原始 datagram 长度，源地址与 payload 在同一 lease 上提交或取消。
- `SocketReceiveLease` 保持 `SocketRef` 生命周期，并实现 VFS `VfsReadLease` 适配；
  `recvfrom` 和 `recvmsg` 直接复用同一 driver lease。
- 补齐 `MSG_DONTWAIT`、`MSG_PEEK`、`MSG_TRUNC` 及无效 `MSG_OOB`/`MSG_ERRQUEUE` 的
  处理，并区分 `EBADF`、`ENOTSOCK`、`EFAULT` 和 iovec 数量错误。
- reservation 在 prepare/commit 异常和 Drop 路径都会清除，避免 socket 永久卡在 Busy。
- 已从 LTP fast-exit 列表移除通过的 `recv01`、`recvfrom01`。

## 语义说明

Linux host 差分显示：测试主机上的 TCP 跨页 fault 返回 `EFAULT` 且未消费，UDP 首字节
fault 会消费 datagram。本任务按既定验收契约实现更强的可恢复语义：TCP partial fault
提交已复制前缀，UDP 首字节 fault 保留整包。UDP 有部分 payload 已复制时提交整包。

`readv(2)` 仍有逐 iovec 调用 legacy read 的问题，属于 RIO-09；本任务未把向量读取改动
混入 socket 提交。
