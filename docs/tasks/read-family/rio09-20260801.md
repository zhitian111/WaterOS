# RIO-09 完成报告：向量与定位读取

## 结果

RIO-09 已完成实现。`readv(2)` 现在完整导入 iovec descriptor 后只建立一次 source
lease，再按 iovec 顺序 scatter；`pread64(2)` 和 `preadv(2)` 使用有界、可失败分配，
且不修改共享 OFD offset。原有逐 iovec 破坏性读取、用户长度直接分配、`preadv` 聚合
完整结果和热路径 `info!` 已移除。

## 修改内容

- 新增 syscall 内部 `ImportedIoVecs`，使用 `checked_mul/checked_add` 导入 descriptor，
  `iovcnt` 上限为 1024，分配失败返回 `ENOMEM`。
- zero-length iovec 允许 NULL base；非零 NULL base 返回 `EFAULT`；总长度超过
  `SSIZE_MAX` 返回 `EINVAL`，合法大请求按 `MAX_RW_COUNT` 和 4 MiB staging 上限短读。
- `readv` 在导入全部 descriptor 后获取单个 `VfsReadLease`。首字节 fault 取消 lease，
  后段 fault 只提交并返回已复制前缀，record/stream 差异继续由具体 lease 决定。
- `pread64` 先验证 fd、访问模式和 positional-read 能力，再处理 offset、长度和用户
  指针；单次 staging 不超过 4 MiB，部分用户复制返回实际进度。
- `preadv` 复用同一 iovec cursor，以 64 KiB staging 循环 `read_at` 并直接 scatter，
  不再构造接近用户 count 的 gathered Vec。
- 不可 seek 的 pipe/socket/eventfd 返回 `ESPIPE`，目录返回 `EISDIR`，只写文件返回
  `EBADF`，负 offset 返回 `EINVAL`。
