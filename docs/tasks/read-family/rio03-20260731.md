# RIO-03 实施报告：共享 open-file-description 状态

## 结果

已为普通文件、目录、procfs 文件及目录建立每次 `open` 独立、在
`dup/dup2/dup3/fcntl(F_DUPFD)/fork` 后共享的 OFD 状态：

- 文件偏移使用 `VfsOpenDescriptionState::offset`；
- `O_APPEND/O_NONBLOCK` 等 status flags 由同一 OFD 的副本共享；
- `FD_CLOEXEC` 仍保存在 fd table 中，每个 descriptor slot 独立；
- pipe 同方向 endpoint、字符设备、Unix socket 和 inet socket 的
  `O_NONBLOCK` 状态随 duplicate/fork 共享；
- 独立调用两次 `open` 会创建两个状态，偏移互不影响。

核心 API 位于：

```rust
pub struct VfsOpenDescriptionState {
    offset: AtomicU64,
    status_flags: AtomicU32,
    reservation_generation: AtomicU64,
}
```

具体句柄仍创建独立 wrapper，内部通过 `Arc<VfsOpenDescriptionState>` 共享
OFD 标量状态。这样没有新增覆盖 ext4、pipe wait 或 network I/O 的 OFD 自旋锁。
`reservation_generation` 仅为 RIO-04 的 prepared-read 事务预留，本任务不实现提交
协议。

## 涉及范围

- `wateros-vfs/vfs-api/api-v0`：共享 OFD 基础类型与自测。
- `wateros-vfs/vfs-impl/impl-fs-bridge`：普通文件、目录、procfs 的 offset/status。
- `wateros-vfs/vfs-impl/impl-fd-session`：字符设备状态与 descriptor flag 测试。
- `wateros-ipc/ipc-pipe`：dup/fork endpoint 共享 pipe status。
- `wateros-driver/driver-network`、`wateros-syscall/.../unix_sock.rs`：socket status。
- `wateros-vfs/src/lib.rs`：真实文件系统 OFD smoke test。

guest 测试覆盖 `open -> dup -> a/b`、关闭 duplicate 后原 fd 继续读 `c`，以及独立
`open` 从 `a` 开始。组件测试覆盖 status flag 共享、pipe clone 状态、pipe
部分关闭和 `FD_CLOEXEC` 的 dup/fork per-slot 语义。

## 后续边界

当前 `SharedIoHandle::with_io()` 仍可能持 fd slot 的 spin mutex 执行阻塞 I/O；
并发读取的 offset 预留、用户拷贝后的按字节提交及同一 fd 阻塞时避免其他 CPU 自旋，
统一由 RIO-04 完成。`pre/final/BuildStorm` 全量回归按约定留到夜间授权后执行。
