# RIO-01 读取访问模式与错误顺序

## 根因

`sys_read()` 在 fd 校验前处理 `count == 0` 和空指针，导致无效 fd、目录和只写句柄
返回错误 errno。VFS `open_accmode()` 默认只读又会掩盖未实现访问模式的句柄；
`BufferedFileHandle` 还把所有可写打开错误报告为 `O_RDWR`。

## 修改

- `VfsIoHandle::open_accmode()` 改为强制契约，所有句柄必须显式实现。
- 增加无 I/O 的 `validate_read_access()`；`O_WRONLY` 返回 `BadFd`，目录覆盖为
  `NotAFile`。
- 普通文件、内建设备和 devfs 字符设备保存由 open flags 得到的真实 accmode。
- pipe 两端分别声明 `O_RDONLY/O_WRONLY`；console stdin/stdout 分别只读/只写；
  socket、socketpair、eventfd 和 epoll 声明 `O_RDWR`。
- `sys_read()` 在长度和用户指针判断前验证 socket/fd、`O_PATH`、对象类型和访问模式。

task 注册表、fd 所有权和调度器架构未改变。本任务不处理读取后的 user-copy 回滚，
该部分仍由 RIO-02/RIO-04 负责。

## Linux 对照

宿主 Linux 7.1 x86_64 的 errno 矩阵与任务预期一致。`qemu-riscv64` 用户态模拟器对
`read(-1, NULL, 1)` 返回 `EFAULT`，与宿主内核不同，因此不把用户态模拟器结果作为
该项 errno 优先级的权威依据。

## RISC-V64 短测

OpenSBI、8 核、12 秒 QEMU 上限，实际约 1 秒完成：

```text
invalid fd + count 0          -> EBADF
invalid fd + NULL + count 1   -> EBADF
readable fd + NULL + count 0  -> 0
O_WRONLY regular file         -> EBADF
pipe write end                -> EBADF
directory fd                  -> EISDIR
O_PATH fd                     -> EBADF
UDP nonblocking read          -> EAGAIN
eventfd one-byte read         -> EINVAL
RIO01_DONE failures=0
```

无 panic、fault kill 或 `BadFd` 恢复警告。
