# RIO-04 实施报告

## 结果

本次冻结了 VFS prepared-read 契约，并完成普通文件、页缓存文件、procfs 文件和目录的
接入。`sys_read` 对这些来源不再先推进 OFD offset：数据先在 fd 锁外读入内核 staging，
再按 `copy_to_user_progress()` 的实际复制量提交 offset。首字节 fault 返回 `EFAULT`
且 offset 不变，跨页部分 fault 仅推进已复制字节。

pipe、Unix/inet socket、eventfd 和字符设备仍显式进入 legacy 分支，分别由 RIO-05 至
RIO-08 接入；`VfsIoHandle::prepare_read()` 默认只返回 `Unsupported`，不会隐式调用
破坏性 `read()`。

## 主要更改

- `wateros-vfs-api-v0` 新增 `VfsPreparedRead`、`VfsReadLease`、复制进度和完成结果；
  `VfsOpenDescriptionState` 保存带 generation/offset 的单个 active reservation。
- `impl-fd-session` 只在短 fd-slot 锁内捕获 owned prepared object；`acquire`、文件 I/O、
  user-copy 和 `finish` 均在该锁外执行。
- `impl-fs-bridge` 增加 RAII `ReservationGuard`。任意错误或未 finish 的 Drop 都取消
  reservation；staging 使用 `try_reserve_exact`，OOM 映射为 `ENOMEM`。
- buffered、paged 和 proc 句柄的 dup 共享 backing/OFD 状态。read/write/lseek/truncate
  不能越过同一 OFD 的 active reservation，独立 open 不受影响。
- paged prepared read 持有额外 page-cache open ref，避免并发 close 使读取源失效。
  detached backing 改为共享状态，避免 dup 时在 fd 锁内复制大缓冲。

## 验证

- `timeout 120s make rv_check`：通过。
- `timeout 120s make la_check`：通过。
- 20 秒定向 RISC-V QEMU 用例：通过，输出
  `[vfs] self_test prepared read ok` 和 `RIO04_READ_LEASE_PASS`。
- guest 覆盖无效首地址后 offset 保持 0、有效重读 `"xyz"`，以及跨页 fault 仅复制并
  提交 1 字节。
- 组件自测覆盖 full/partial commit、首字节 fault、Drop cancel、EOF、dup 上的
  read/write/lseek 冲突、独立 open 和 staging OOM。

按白天验证策略，本次未运行 pre/final/BuildStorm 全量套件；完整门禁留待夜间授权。

## 后续约束

当前 reservation 冲突会在释放 fd 锁后协作式 `yield_now` 重试，不会持自旋锁等待。
若压力测试显示同一 OFD 高竞争，应在独立任务中为 `api-v0` 增加实现无关的通知契约，
由 task 层 waitqueue 唤醒，不能在 VFS API 中直接反向依赖调度器。

RIO-05 至 RIO-08 必须复用本次 API，移除对应 legacy read。RIO-09 再统一
`readv/pread/preadv`，不得通过地址预检查或 EFAULT 后 seek 回退规避租约。
