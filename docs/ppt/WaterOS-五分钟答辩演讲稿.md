# WaterOS 五分钟答辩演讲稿

> 对应 `WaterOS (1).pdf`，共 25 页。正常语速约 5 分钟；章节过渡页不展开讲解。

## 第 1 页｜开场（0:00—0:20）

各位老师好，我们是来自山东大学青岛校区的 OuterSystems 团队。今天汇报的项目是 WaterOS：一个使用 Rust 从零构建、面向 RISC-V64 和 LoongArch64、兼容 Linux ABI 的宏内核。下面我将从运行成果、系统架构、核心模块、创新工作和测试情况五个方面进行介绍。

## 第 2—3 页｜目录与章节过渡（0:20—0:25）

首先介绍 WaterOS 已经具备的整体能力。

## 第 4—7 页｜内核简介与运行成果（0:25—1:05）

WaterOS 的目标不是只完成一个能够启动的实验内核，而是构建一套能够承载真实应用的操作系统环境。目前系统支持双架构、多核调度、虚拟内存、文件系统、进程通信、TCP/UDP 网络以及 VirtIO 设备驱动，并通过 Linux ABI 直接运行已有用户程序。

在 QEMU 中，各项功能可以完整运行；在 VisionFive 2 和 Loongson 2K1000 开发板上，也已经实现启动、文件读写和 BusyBox 应用运行。软件生态方面，系统能够使用 APT、PACMAN 等包管理工具安装软件。这里展示的是 Nano-X 图形桌面，以及通过 APT 安装并运行 Vim 的结果，说明系统已经贯通了从内核机制、设备和文件系统到复杂用户应用的完整链路。

## 第 8—9 页｜总体架构（1:05—1:30）

从整体结构看，上层的 BusyBox、LTP 和 Nano-X 通过 Linux ABI 进入内核；内核包含内存、任务、IPC、文件系统、网络和设备驱动等子系统；底层平台层屏蔽 RISC-V64 与 LoongArch64 在启动、页表和中断上的差异。这样的分层使同一套核心逻辑能够在两种架构上复用，同时保持 Rust 实现的类型安全和模块边界。

## 第 10—12 页｜内存与文件系统（1:30—2:05）

内存管理以 4 KiB 页为基本单位，建立从物理页分配、虚拟地址空间到共享映射的完整链路。系统支持按需分页和写时复制：进程创建时先共享只读页面，真正写入时再复制，从而降低 fork 的初始开销；同时通过跨核 TLB 刷新维护多核地址空间一致性。

文件系统则把「从磁盘块到文件」这条链路串起来看：磁盘先被切成一个个 4K 的块；ext4 负责用目录项、inode 和数据块，把这些块组织成有结构的文件；再往上一层，VFS 把所有资源统一收敛成文件句柄——普通文件、/dev/fb0、/proc、pipe、socket 都是 fd，一套 open、read、write 就能访问所有资源，普通文件走页缓存，管道和设备走 fd-session 句柄。

这里用一个例子说明这套设计的价值：显示。显卡提供一块线性帧缓冲 buffer，本质就是屏幕上的像素数组。内核把它包装成 VFS 句柄，在 devfs 里挂成 /dev/fb0；用户程序像操作普通文件一样 open 它，再 mmap 或 write 直接写像素，内核最后把 buffer flush 到 DisplayDevice 上屏。也就是说，画图就是写文件，硬件差异被完整地挡在句柄层后面。

## 第 13—15 页｜任务与多核调度（2:05—2:40）

任务模块统一管理任务、进程和线程，并维护 Ready、Running、Blocking、Sleeping 和 Exited 等状态。调度器为每个 CPU 维护独立运行队列，支持先进先出、基于入队负载的均衡策略，以及结合 CFS `vruntime` 的公平调度。

调度由任务状态变化、周期时钟中断和跨核 IPI 共同触发。发生切换时，内核保存当前上下文、选择下一任务并更新 CPU 本地状态；当其他核心需要重新调度时，通过定向 IPI 发出请求，由此实现多核并行运行和负载迁移。

## 第 16—18 页｜IPC、网络与设备平台（2:40—3:25）

进程通信方面，WaterOS 提供 Signal、Futex、Eventfd、Pipe、消息队列和共享内存。它们统一复用等待队列完成阻塞与唤醒，既覆盖异步通知和用户态锁，也支持字节流通信、事件计数和进程间共享数据。

网络方面，我们基于 smoltcp 实现 TCP/UDP 协议栈，并封装 Linux Socket 语义，使套接字能够进入 VFS 文件描述符表，按照统一方式读写。底层通过网络设备接口同时接入 VirtIO-Net 的 MMIO 与 PCI 设备。

驱动层进一步统一块设备、字符设备、显示、输入和网络设备；平台层则统一启动、时钟、中断、SMP 和内存能力。这样，上层功能不需要感知具体硬件，同一内核可以在不同架构与机器实现之间切换。

## 第 19—21 页｜借鉴、整合与创新（3:25—4:15）

在兼容性设计上，我们借鉴 Linux 的通用 64 位系统调用 ABI、进程和 clone 语义、VMA 与 page cache 思路，以及 SCHED_OTHER、FIFO、futex 和信号等机制。同时复用 smoltcp、ext4 和 virtio-drivers 等开源组件，但并不是简单拼装：我们修复了 ext4 块分配与链接问题，扩展了 VirtIO 区域刷新，并为网络栈实现适配层和全局套接字池。

我们的主要增量体现在三点。第一，通过 Cargo Feature 和 API/Impl 分离，用一套源码组合不同架构、平台和能力。第二，将架构相关的启动、页表和中断差异收敛到底层，上层模块可以跨架构复用。第三，在机制上实现统一阻塞式 I/O、缓存分层与 ghost history 准入，以及多策略调度和基于 IPI 的 SMP 负载均衡。

## 第 22—24 页｜总结、验证与规划（4:15—4:50）

目前 WaterOS 已完成双架构支持、多核调度、按需分页与写时复制、多文件系统、完整 IPC、网络、设备驱动和图形桌面环境。我们使用 LTP 验证 Linux 兼容性，使用 stress-ng 进行压力测试，使用 lmbench 测量基础性能，并通过 BusyBox 等真实工具链进行综合回归。这些测试共同验证了系统不是单点功能演示，而是具备持续运行和承载应用的完整性。

下一阶段，我们将重点推进跨核主动负载均衡和用户栈按需增长，加入 cgroup、capability 与进程资源统计，继续强化高并发 fork/exit 场景下的资源回收，并完善设备热插拔以及 procfs、sysfs 的系统可观测信息。

## 第 25 页｜结束（4:50—5:00）

以上就是 WaterOS 的项目汇报。我们希望通过 Rust、双架构抽象和 Linux 生态兼容，探索一条兼顾安全性、可移植性与实际应用能力的操作系统实现路径。感谢各位老师的聆听，欢迎批评指正。
