# WaterOS 开发任务列表

本文档为**共享任务列表**的示例与模板。建议实际协作时使用 **GitHub Issues + Projects** 或 **GitLab Issues + Board** 管理，便于认领、关联 PR、自动关闭。若暂时不用 Issue 系统，可在此维护一份简易清单并定期同步。

---

## 使用说明

- **状态**：`待办` → `进行中` → `Review 中` → `已完成`
- **类型**：`API 设计` | `实现` | `Bug 修复` | `文档`
- **认领**：在任务后写上负责人；认领后请把状态改为「进行中」，并创建对应分支（如 `impl/fs-devfs`）。
- **关联**：完成时在任务中填上 PR 链接；合并后改为「已完成」。

## 与工作流对应

1. **核心开发**：新增「API 设计」或拆出「实现 xxx」任务，写清依赖的 API（如 api-v0）。
2. **实现开发**：认领任务 → 创建 `impl/<组件>-<名>` 分支 → 开发 → 提 PR → 在本表或 Issue 中填 PR 链接。
3. **Review 通过并合并**：将任务标为「已完成」，必要时删除已合并分支。

若使用 GitHub：可为每个任务开一个 Issue，用 label 区分 `api-design`、`impl`、`component:fs` 等，PR 中写 `Closes #Issue编号` 即可在合并时自动关闭。
