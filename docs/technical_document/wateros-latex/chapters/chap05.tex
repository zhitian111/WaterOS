\chapter{总结与后续工作}

\section{工作总结与项目特色}

\wateros{}已经形成从平台启动、trap、分页、任务调度到用户ELF执行的内核主路径，并在这条路径上接入文件系统、VFS、fd、procfs、pipe、futex、socket、凭证、klog和Linux generic 64-bit syscall兼容层。RISC-V64与LoongArch64分别处理启动参数、trap frame、页表token、TLB刷新和VirtIO总线差异，上层MM、task、FS/VFS、IPC和syscall逻辑保持复用。

项目实现上的主要特点如下：

\begin{itemize}
  \item \wosstrong{组件化组织。}平台、驱动、MM、FS、VFS、task、syscall等核心模块采用API、实现和聚合导出的结构，根crate负责组合，具体能力留在组件内部。
  \item \wosstrong{双架构边界清晰。}架构差异集中在平台、页表、trap和设备总线层，用户态可见的fd、cwd、VFS、进程和syscall语义保持一致。
  \item \wosstrong{用户态路径连续。}用户ELF装载、地址空间切换、系统调用分发、fd表、procfs、tmpfs、futex、socket和文件系统读写已经连接到同一条运行路径。
  \item \wosstrong{诊断入口完整。}启动阶段保留MM、驱动、FS、VFS、网络和用户ELF的分层日志，配合QEMU日志、PC监视和符号解析工具定位panic、死循环、unknown syscall和用户程序退出问题。
\end{itemize}

\section{后续完善方向}

后续完善沿已跑通的用户态主路径展开，重点收紧Linux语义、长时间运行稳定性和双架构一致性。主要工作包括：

\begin{enumerate}
  \item \wosstrong{补齐双架构同构验证。}RISC-V64和LoongArch64已经共用上层task、MM、FS/VFS、IPC和syscall逻辑，后续重点检查动态链接、\syscall{clone}参数、TLS、页表/TLB刷新和VirtIO-MMIO/VirtIO-PCI差异，保证相同用户程序在两条路径上得到一致的返回值和错误码。
  \item \wosstrong{细化进程、线程和信号语义。}在已有fork、exec、wait、futex和调度接口基础上，继续补齐线程组、\syscall{clone3}、实时信号、job control、robust futex和更多调度策略相关语义，减少复杂用户程序对Linux行为差异的感知。
  \item \wosstrong{增强文件系统写路径。}围绕ext4\_rs、tmpfs、VFS mount table和page cache，继续完善\syscall{fsync}、rename/unlink、busy umount、多挂载实例和脏页写回，避免文件大小、目录项和页缓存状态在异常路径下不一致。
  \item \wosstrong{收紧资源回收和失败回滚。}fd、socket、shm、task、page cache和内核堆分配都已经进入用户态主路径，后续重点处理OOM、dup/close并发、socket关闭、共享内存attach失败和任务退出时的回收顺序。
  \item \wosstrong{完善网络和设备路径。}在virtio-net、smoltcp、AF\_UNIX和socket fd registry的基础上，继续处理TCP/UDP长连接、loopback、后台server、多进程socket生命周期，以及不同QEMU网络参数下的设备初始化差异。
  \item \wosstrong{改进运行记录和定位工具。}保留QEMU串口日志、PC监视、符号解析和日志解析工具，进一步统一RISC-V64/LoongArch64的运行记录格式，使panic、死循环、unknown syscall、用户程序断言失败和资源泄漏都能更快定位到对应模块。
\end{enumerate}

\section{AI工具使用说明}

本队在开发过程中使用AI辅助编程工具生成或改写部分内核代码。凡经AI参与完成的代码块，均在源码中以\code{// 由AI完成}、\code{// 本模块代码由AI完成}等注释标注；队伍在合并前对生成结果做编译、运行测例和语义核对，标注仅用于追溯来源，不表示未经审查即可交付。且为了项目符合我们最初设计的预期，在内核代码中，我们仅将AI生成代码用于了Impl中，具体的struct，trait定义，即Api系列文件夹下的代码以及通过原语组合出的模块的功能，这些设计和实现均由团队成员亲自完成。
另需说明，在使用AI辅助debug的时候，我们使用AI批量插入了log信息，以方便我们进行调试。但目前依旧存在清理不完全的问题，其中有一部分log代码仍是AI生成的，但因为不影响核心功能，故此处不再做列举。

其次AI也同样适用于辅助我们完成本文档的编写，包括但不先于：（1）检索每个文件中的AI生成标记并汇总路径和行范围，并随机提取代码片段作为代表。（2）辅助完成文档内错误用语的勘误，文档正文在写完之后由AI进行了格式化和润色。（3）辅助完成文档内的一些重复性工作的自动化，如在构建文档项目时，通过AI完成目录结构初始化。且除此以外为了保证讲解视频效果我们使用了部分AI配音或语音校准。
