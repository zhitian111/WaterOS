\section{内核集成：异常与系统调用入口}

用户态运行路径上的异常、中断与系统调用并不落在单个\code{wateros-*} crate内，而是由组合层在任务子系统初始化之后注册架构trap handler，把汇编入口交出的trap原因分流到系统调用、内存管理、任务与平台子系统。下文各组件节只描述本crate提供的接口与实现；本节说明跨组件衔接。

热路径上，用户态系统调用经分派写回返回值；页错误先尝试写时复制或延迟映射，失败则向当前任务投递段错误信号；监督态定时器中断按与内核主循环一致的周期重装并驱动调度tick。内核态不可恢复trap进入停机循环；用户态无法继续执行的fault在记录诊断后结束当前进程组。

\begin{rustcode}
match trap_cause {
    // 用户态 ecall：读调用号与六个参数，分派 syscall 并写回 a0
    // exec 成功时已替换整帧，不推进 sepc；其余 syscall 将 PC 前进一条指令宽度
    // rt_sigreturn 走独立恢复路径，失败则杀进程组
    TrapCause::Exception(Exception::UserEnvCall) => {
        let ret = dispatch_syscall_from_trap(nr, args);
        if !exec_succeeded(nr, ret) {
            cx.add_user_pc(SYSCALL_INSN_BYTES);
            cx.set_syscall_ret(UserRet(ret));
        }
    }
    // 用户页错：先 COW，再 lazy 映射；仍失败则 SIGSEGV，必要时 kill 进程组
    TrapCause::Exception(Exception::InstructionPageFault)
    | TrapCause::Exception(Exception::LoadPageFault)
    | TrapCause::Exception(Exception::StorePageFault) => {
        if mm::kernel_mm::handle_user_page_fault(aspace, addr, access) {
            return;
        }
        syscall::raise_current_signal(SIGSEGV);
    }
    // 监督态定时器：重装 TIMER_REARM_MS，递增 tick，触发 timer_tick 与 schedule_tick
    TrapCause::Interrupt(Interrupt::SupervisiorTimer) => {
        platform::timer::set_timer_after_ms(TIMER_REARM_MS);
        syscall::timer_tick(cx.returns_to_user());
        task::schedule_tick();
    }
    // 内核态页错与其余未预期 trap：fatal_kernel_trap 停机，避免 sret 回到损坏 PC
    _ => { /* fatal_kernel_trap 或用户态信号/kill */ }
}
\end{rustcode}
