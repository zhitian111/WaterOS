\subsection{ipc-signal}

\code{ipc-signal}在\code{feature signal}下由父聚合导出\code{ipc::signal::with\_registry}与 API 类型。与 pipe、futex 不同，\code{SignalRegistry}状态机实现在聚合\code{ipc-signal/src/lib.rs}本身，而非独立\code{impl-task}；\code{signal-impl/impl-dummy}仅为未挂接的链接桩。syscall 与 trap 经\code{with\_registry}在全局\code{Mutex<SignalRegistry>}锁下访问进程 disposition、pending、三类\code{setitimer}，以及线程 mask、pending、\code{sigsuspend}/\code{ppoll}临时掩码与\code{sigwait}。

\paragraph{SignalRegistry 实现要点。}
进程级\code{ProcessSignalState}保存\code{actions[NSIG]}、进程\code{pending}与 real/virtual/prof 三类 interval timer；线程级\code{ThreadSignalState}保存\code{mask}、线程\code{pending}与 suspend/poll 掩码栈。\code{send\_process}/\code{send\_thread}按 disposition 分类为\code{Ignored}、\code{Pending}、\code{Terminate}、\code{Stop}、\code{Continue}；\code{take\_deliverable}合并线程与进程 pending、扣除 mask，并应用\code{SA\_NODEFER}/\code{SA\_RESETHAND}。

\begin{rustcode}
pub fn take_deliverable(&mut self, task_id: usize) -> Option<PendingSignal> {
    let deliverable = thread.pending.union(process.pending).difference(thread.mask);
    let sig = deliverable.first_signal()?;
    // 清除 pending、构造 handler_mask、可选 SA_RESETHAND
    Some(PendingSignal { signal: sig, action, previous_mask })
}
\end{rustcode}

\code{fork\_process}复制 disposition 与继承 mask；\code{exec\_process}重置用户 handler；\code{expire\_realtime}与\code{account\_cpu}驱动\code{SIGALRM}/\code{SIGVTALRM}/\code{SIGPROF}路径。单元测试覆盖 timer 推进与 pending 合并。

\paragraph{缺口。}
无实时信号队列深度限制外的完整 RT 语义；无 altstack；job control 进程组语义未实现。
