\section{wateros-mm}

\wateros 的内存管理一级组件，对上通过聚合 crate \code{wateros-mm} 暴露\code{mm::api}（契约）、\code{mm::frame\_alloctor}（物理帧）、\code{mm::kernel\_mm}（bring-up 与用户地址空间操作）等门面；对下按 Cargo feature 在\code{impl-sv39}、\code{impl-loongarch64}、\code{impl-dummy} 三套页表实现间互斥选择。页大小固定为 4\,KiB，与 RISC-V Sv39 常用叶子页一致。

根内核通过\code{mm = \{ package = "wateros-mm", ... \}}依赖本组件。\code{wateros-task}在 fork/exec 路径持有\code{LoadedElf::user\_aspace\_ptr}与地址空间 token；\code{wateros-syscall}经\code{mm::api}的\code{MmapOps}、\code{HeapBrk}、\code{UserMemoryOps}处理用户内存系统调用；trap 路径调用\code{mm::kernel\_mm::handle\_user\_page\_fault}与\code{handle\_cow\_fault}。聚合层刻意不导出\code{pagetable::*}等页表内部类型，依赖方应只使用\code{mm::api}与\code{mm::kernel\_mm}。

默认 feature \code{api-v0}仅链接\code{impl-dummy}页表桩，可编译但不装载 ELF、不 fork。真实 bring-up 须在根\code{wateros}上启用\code{mm/impl-sv39}（RISC-V）或\code{mm/impl-loongarch64}（LoongArch64），二者通过\code{active\_mm\_impl}条件编译保证符号互斥。物理帧分配默认走\code{frame-alloctor}的\code{impl-stack}。

\begin{rustcode}
pub use api_v0 as api;
pub use frame_alloctor;
// impl-sv39 与 impl-loongarch64 互斥，经 active_mm_impl 转发 user_aspace / kernel_mm
\end{rustcode}
