\section{内存管理组件}

内存管理组件\code{wateros-mm}负责虚拟地址语义、页表实现、物理帧分配与用户态装载，对上暴露契约API、帧分配器和内核bring-up入口，不把页表内部类型泄漏给依赖方。页大小固定为4\,KiB，与RISC-V Sv39常用叶子页一致；大页不在本阶段表达。

根内核在内存子系统初始化阶段建立内核页表与可用物理帧池；任务在fork与exec路径持有用户地址空间句柄；系统调用层经契约处理内存映射、堆扩展与用户缓冲区访问；陷阱路径缺页时回调本组件的缺页与写时复制处理。默认feature仅链接占位页表，可编译但不装载ELF、不fork；真实bring-up须启用Sv39或LoongArch64实现，二者通过条件编译互斥。

物理帧默认走栈式LIFO分配器，带引用计数以支撑fork写时复制；统计信息可供proc类查询。NUMA策略当前为单节点桩，满足bring-up系统调用返回值即可；帧分配器为单核实现，无buddy或slab分层。

// mm/lib.rs: trap 缺页与 COW 由 kernel_mm 门面转发
pub fn handle_user_page_fault(
    aspace_ptr: usize,
    fault_addr: usize,
    access: api_v0::mmap::PageFaultAccess,
) -> bool {
    // 惰性 mmap / 栈扩展 / brk 等按需映射
    let mut alloc = crate::frame_alloctor::GlobalPhysFrameAllocator;
    crate::user_aspace::with_user_aspace_mut(aspace_ptr, |aspace| {
        MmapOps::handle_page_fault(aspace, &mut alloc, VirtAddr(fault_addr), access)
    })
    .unwrap_or(false)
}

pub fn handle_cow_fault(aspace_ptr: usize, fault_addr: usize) -> bool {
    // fork 后首次写触发写时复制
    impl_sv39::kernel_mm_impl::handle_cow_fault(aspace_ptr, fault_addr)
        .unwrap_or(false)
}
\end{rustcode}
